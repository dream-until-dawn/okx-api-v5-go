# 能力范围与边界

这份文档说明 SDK **能做什么、不做什么、哪些部分尚未被真实验证**，
帮助你在引入前判断它是否适合你的场景。所有结论都来自对实盘与模拟盘账户的实测，
不是照抄官方文档。

## 定位

**单账户的 USDT 本位永续合约程序化交易，以及回测所需的数据供给。**

结构体字段是按「逐仓 + 永续 + 双向持仓」这一组合，用真实报文逐个核对后选定的。
其他品种（现货、交割、期权）的接口能调通，但返回结构里没有它们的专属字段。

## 覆盖范围

48 个 REST 端点，按官方文档分组挂在四个 service 下，外加三类 WebSocket 连接（私有连接兼具下单能力）。

| 领域 | 覆盖 |
| --- | --- |
| 行情 `Market` | 行情快照、成交价 / 标记价 / 指数 K 线（含历史与跨区间分页）、深度、公开成交、历史逐笔成交、指数行情 |
| 公共数据 `Public` | 产品信息、标记价、资金费率（含全量历史）、仓位档位、持仓量、限价范围、服务器时间 |
| 账户 `Account` | 余额、持仓、历史持仓、账户配置、杠杆查询与设置、最大可开 / 可用、持仓模式、账单、手续费率、逐仓保证金增减 |
| 交易 `Trade` | 下单 / 撤单 / 改单 / 市价全平、批量操作、订单与成交查询、策略委托、断线自动撤单 |
| WebSocket | 公共 / 业务 / 私有三类连接；自动登录、心跳、断线重连与重订阅；私有连接支持 WS 下单通道 |

未封装的接口可以用泛型 `Do` 直接调用，不必等 SDK 更新：

```go
resp, err := okx.Do[map[string]any](ctx, client, http.MethodGet,
	"/api/v5/asset/balances", url.Values{"ccy": {"USDT"}}, nil, true)
```

## 明确不做的部分

以下接口域**整片没有封装**，但都真实存在且可用泛型 `Do` 调通（已实测确认）：

| 领域 | 路径前缀 | 说明 |
| --- | --- | --- |
| 资金账户 | `/api/v5/asset/*` | 划转、充提、资金账单 |
| 子账户 | `/api/v5/users/subaccount/*` | 子账户管理与资金划转 |
| 交易大师 | `/api/v5/tradingBot/*` | 网格、定投 |
| 跟单 | `/api/v5/copytrading/*` | 带单与跟单 |
| 理财 | `/api/v5/finance/*` | 余币宝、链上赚币 |
| 大宗交易 | `/api/v5/rfq/*` | 询价与报价 |
| 市场统计 | `/api/v5/rubik/stat/*` | 多空比、主动买卖量、持仓量与成交量 |

另外几条设计上的边界：

**字段按永续场景取舍。** 期权希腊字母、币币杠杆的借币与负债、交割结算相关字段
在结构体里都没有——它们在本 SDK 面向的场景下实测恒为空。做期权会缺一大片。

**深度频道不维护本地订单簿。** `books` 是增量推送，SDK 把 `action`（snapshot / update）
和原始数据交给你，合并逻辑需要自己实现。只需要全量快照时用 `books5`。

**泛型响应假定 `data` 是数组。** 少数接口（如 `/api/v5/market/index-components`）
返回的是对象，`Response[T].Data []T` 解不了，需要自己 `json.Unmarshal`。

**单账户单实例。** 多账户请创建多个 `Client`，SDK 不提供账户池或统一调度。

## 已验证到什么程度

| 路径 | 验证情况 |
| --- | --- |
| REST 公共接口 | 实盘跑通 |
| REST 私有读接口 | 实盘 17/17、模拟盘 16/16 全通 |
| REST 写接口（下单 / 改单 / 撤单 / 批量） | **仅模拟盘**验证受理（12/12），全程 reduceOnly 远离市价挂单，零成交 |
| WebSocket 三类连接 | 实盘跑通：私有频道登录 + 账户与持仓推送；公共与业务频道 30 秒内收到 700+ 条推送 |
| WS 下单通道 | 模拟盘验证：单笔与批量下单、撤单、12 路并发应答关联无串号 |
| 断线自动撤单 | 模拟盘验证设置与取消倒计时 |
| 逐仓保证金调整 | 模拟盘验证增加成功（强平价随之推远）；减少受维持保证金限制，实测即使按 1% 减也可能被交易所拒绝（59301） |
| 内置限流器 | 离线确定性测试覆盖突发、稳态、并发公平性与取消归还 |
| 历史数据分页 | 实盘拉 3 天 1m 共 4320 根，零重复、零缺口、零乱序、边界精确 |
| 断线重连与重订阅 | 伪造服务端掐线验证；真实网络下未做长时验证 |
| 限频重试 | 仅伪造服务端覆盖 |

## 已知风险

**实盘写路径从未被交易所受理过。** 验证用的实盘 Key 是只读权限，下单只验证到
「被正确拒绝」（HTTP 401 + `code=50120`）。模拟盘验证了完整写路径，但**实盘首次
下单仍属未走过的路径**，建议第一笔用最小数量试。

**限频重试路径未被真实触发。** 连发 30 次请求没有撞上限流，429 的重试分支只有
伪造服务端覆盖。SDK 内置了令牌桶限流器（`WithRateLimit`），但默认不启用。

**WebSocket 下单没有带来可观测的延迟优势。** 实测同一环境下 WS 与 REST 下单往返
分别是 354ms 和 362ms，差异在噪声范围内——跨境链路上往返时延占绝对大头。
WS 交易省掉的是每次请求的签名与报文构造，收益要在低延迟链路或高频场景才显现。

**WS 下单需要 instIdCode。** OKX 要求 WebSocket 下单带上产品数字编码，SDK 会自动
解析并缓存，但**首次用到某个产品会触发一次 REST 查询**。延迟敏感的策略请在启动时
调用 `PreloadInstrumentCodes` 预热。

**竞态检测未运行。** 开发机没有 C 编译器，`go test -race` 无法执行。并发正确性
目前只有代码审查和普通测试覆盖；WebSocket 部分有多个 goroutine 与锁，是最可能
藏问题的地方。使用前建议在你的环境跑一次 `go test -race ./...`。

**长时间运行未验证。** WebSocket 最长连续运行约 30 秒。重连是在伪造服务端上掐线
验证的，真实网络下的长期表现（交易所主动断连、半开连接、网络抖动）没有数据。

**WS 回调是同步调用的。** 消息在读循环里直接调用你注册的 handler，handler 阻塞
会阻塞整条连接的后续消息。耗时逻辑请自行投递到别的 goroutine。

**资金费率历史只有约 3 个月，且静默截断。** 实测 `funding-rate-history` 是约 92 天的
滚动窗口（BTC/ETH-USDT-SWAP、BTC-USD-SWAP 均为 277 条、2026-06-01 起），更早的区间
返回空数组。已用绕过分页器的直接请求确认边界来自交易所而非 SDK：`after` 指向 95 天
前及更早一律为空。实盘与模拟盘一致，不受 `WithSimulated` 影响。
`FundingRateHistoryAll` 对此不报错，超过 3 个月的回测直接累加返回值会严重低估资金费。

**模拟盘会截断公共历史行情。** `WithSimulated(true)` 不只影响交易——实测模拟盘的
K 线一律只回溯到 2022-05-27（ETH/BTC-USDT-SWAP 的成交价与标记价均为 1558 根），
而实盘可回溯到合约上线。且两条序列在同一点齐断，在模拟盘上比较「标记价与成交价
谁更深」会得到「一样深」的假象，实际是「一样取不到」。拉历史数据请用不带
`WithSimulated` 的客户端。

**文档中的日期一律为港时（UTC+8）。** OKX 的日线按港时对齐——1D K 线开盘于
UTC 16:00 即港时 00:00，所以同一根 K 线在 UTC 口径下会显示为前一天。
`Candle.Time()` 按 Go 惯例返回本地时区时间，在非 UTC+8 的机器上格式化会得到
不同日期；需要固定口径时请显式 `.UTC()`，或直接比较毫秒时间戳。

**标记价历史比成交价浅，且 SDK 不会报错。** 实测标记价与指数 K 线一律不早于
2020-01-01 港时（原始时间戳 1577808000000 = 2019-12-31 16:00 UTC），
成交价则可回溯到合约上线当天，因此 2020 年前上线的合约存在开头缺口：
BTC-USD-SWAP 差 379 天、BTC-USDT-SWAP 差 34 天、ETH-USDT-SWAP 差 32 天；
2020 年后上线的（如 SOL-USDT-SWAP）同深。`CandleHistory` 会如实返回交易所给出的
范围而不对缺口报错——依赖标记价建模强平的回测若把起点设在 2020-01-01 之前，
会得到一段缺少强平判定依据的数据。样本 5 个合约，这条界线是观察结论而非官方承诺。

**签名依赖本地时钟。** 时钟偏差过大会被交易所拒绝（`code=50102`）。SDK 提供了
`Public.ServerTime` 但**不会自动校准**，需要自己定期核对。

## 版本承诺

当前是 `v0.x`，**API 不承诺稳定**，v1 之前可能有破坏性调整。
建议在 `go.mod` 里锁定具体版本而不是跟随 `main`。
